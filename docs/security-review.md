## Verification and repeatable evidence

`npm test` builds successfully and passes all 20 tests under Node 26.9.0 / npm 12.1.0. Real loopback end-to-end runs cover SMTP STARTTLS plus IMAP implicit TLS and the complementary SMTP implicit plus IMAP STARTTLS. Separate tests reject absent STARTTLS before either protocol sends credentials, reject untrusted SMTP/IMAP certificates and check the minimum TLS/certificate settings. Legacy TLS versions and every possible certificate-error variant are not exhaustively tested.

Semgrep Community Edition 1.183.0 with `p/javascript`, `p/nodejs`, `p/security-audit` and three local transport rules scans all eight application TypeScript files and the JavaScript release-evidence script (nine files total): 92 applicable rules, approximately 100% parsed, zero final findings/errors. The local rules reproduce two baseline missing-transport-policy findings and clear after the fixes without suppressions. Community rules alone did not catch those missing policies. No paid engine/account is used. Registry rules can evolve; retained results include the rule IDs and executed version. The source-SHA CI artifacts expire after 90 days; release evidence must be retained durably.

The assurance script generates `release-artifacts/source-manifest.json`, `audit.json`, `semgrep.json`, `tests.txt`, `sbom.spdx.json`, `components.json`, package files/tarball, source/dependency archives, `recovery.json`, `recovery-tests.txt` and SHA-256 checksums. It verifies archive bytes against lockfile integrity, recovers every source hash, seeds an initially empty npm cache from only the archived tarballs, performs `npm ci --offline --ignore-scripts`, and reruns all 20 tests. Any failed gate terminates the bundle build. Generated binary assets stay outside Git and are intended as versioned release assets.

The actual supplier of this project is Sami. Upstream package metadata is retained as provenance; uncertain suppliers use [SPDX's explicit NOASSERTION representation](https://spdx.github.io/spdx-spec/v2.3.1/package-information/). Known unknowns are recorded rather than silently omitted or turned into a requirement for external supplier attestations. The programme uses the normative 2021 NTIA component-record model referenced by ISO/IEC 18974, not a claim of independent compliance with later procurement profiles.

`git diff --check` passes. A TypeScript ESLint-parser approach was discarded because its current peer contract excludes this project's intentional TypeScript 7.0.2; Semgrep avoids adding an incompatible development dependency. GitHub private vulnerability reporting is enabled, the repository is public, and authenticated advisory access was verified; no past reporter response is fabricated.

## Release and conformance boundaries

The manually dispatched `.github/workflows/release.yml` requires an existing reviewed version tag equal to main's exact checked-out commit and package version. It runs the evidence/recovery gates, attests package provenance and the SPDX record with GitHub OIDC, publishes the exact inspected tarball with npm provenance, verifies the registry tarball integrity, and retains source/component/result archives as GitHub release assets. Registry publication uses the release workflow’s authorized npm authentication; GitHub OIDC independently signs the provenance and attestations. The workflow also uploads the inspected archive as a CI artifact before attempting npm publication; that expiring copy does not replace durable release retention. It has no scheduled or automatic release trigger. Current official contracts: [npm trusted publishing](https://docs.npmjs.com/trusted-publishers/), [npm provenance](https://docs.npmjs.com/generating-provenance-statements/), and [GitHub actions/attest](https://github.com/actions/attest).

The workflow is prepared source, not an executed hosted release. Hosted CI, final committed/tagged source, durable uploaded archives, actual provenance and native npm/GitHub release read-back remain publication steps. The [programme review](evidence/programme-review.md) records the completed scoped policy/role/competence/awareness/resource/operating review and explicitly preserves the final declaration boundary. No ISO/IEC 5230, external ISO certificate, passing OpenSSF badge or completed ISO/IEC 18974 conformance is asserted.
